# Calligraphy Batch Tool — Design Spec

_Date: 2026-06-24 · Status: **awaiting user review** · Scope: Project 1 of 2 (the two-stage wholesaler approval workflow is a SEPARATE spec)._

## 1. Goal

An **admin-only** tool inside loloshop that turns a list of student names into **Arabic calligraphy name-plate images** for graduation sashes — generated by AI, spelled correctly, downloadable in bulk. Operated by the shop admin; not exposed to wholesalers/retail.

## 2. Context & key constraints (all empirically established 2026-06-24)

- **Why AI, not the loloagent engine:** the pure-code engine (`~/Desktop/loloagent`) is the $0 endgame but tops out ~6/10 today. AI ships the dramatic look now.
- **Region lock:** the user cannot enable Google Cloud paid billing (country unsupported). All AI image calls go through **OpenRouter** (`/api/v1/images`), which works internationally. OpenRouter does **not** offer Google's 50%-off batch mode, so cost = standard per-image rate.
- **Model decision — LIVE TESTED on the 10 reference names:**

  | Model | Res | $/sheet (10 names) | Spelling | Quality |
  |---|---|---|---|---|
  | `google/gemini-2.5-flash-image` | 1K | $0.04 | ❌ 0/10 garbled | dead |
  | **`google/gemini-3.1-flash-image` (Nano Banana 2)** ✅ **CHOSEN** | **2K** | **$0.10** | ✅ 10/10 | ~7, clean Naskh |
  | `google/gemini-3-pro-image` | 4K | $0.24 | ✅ 10/10 | ~8, bolder (optional premium) |

  **Production default = Nano Banana 2 @ 2K.** Per student ≈ **$0.010** → ~**$24 per 1,000-student school** → ~**$300/mo at 30k**. Pro 4K kept as an optional "premium" model toggle (~$720/mo).

## 3. In scope / out of scope

**In:** admin UI, 3 input modes, OpenRouter generation (10 names/sheet), dedup + progress, crop sheet → individual plates, proof + single-name re-roll, ZIP download, `calligraphy_plates` table.

**Out (separate specs/sessions):** the two-stage wholesaler approval workflow; wholesaler/retail self-service; the loloagent engine; local-GPU/ControlNet route.

## 4. Architecture (follows existing loloshop conventions)

```
Frontend (Next 16 app router, admin-gated)
  app/admin/calligraphy/page.tsx — input modes, generate, progress, proof grid, download
        │  HTTP (JWT admin)
Backend (Express 5)
  routes/calligraphy.js → controllers/calligraphyController.js
        ├─ lib/db.js (query/tx)                 — calligraphy_plates table
        ├─ lib/openrouter.js (NEW)              — POST /api/v1/images, reads OPENROUTER_API_KEY (server-side .env only)
        ├─ lib/sheetCrop.js (NEW)               — row-projection crop: sheet → N individual plate PNGs
        └─ lib/upload.js                        — store PNGs under /uploads/calligraphy/
```

- Auth: `requireRole('admin')` on every endpoint.
- Errors: existing `{ error: <Arabic msg>, code: 'ERR_*' }` shape.
- Migration: `db/migrations/043_calligraphy_plates.sql`.
- Add deps: an image lib for cropping (`sharp` preferred; `jimp` fallback).

## 5. Data model — `calligraphy_plates`

| column | type | notes |
|---|---|---|
| `id` | UUID PK | |
| `wholesaler_id` | UUID NULL FK→wholesalers | NULL for typed/txt jobs |
| `student_id` | UUID NULL FK→students | set for grab-by-wholesaler; **dedup key** |
| `source` | enum(`typed`,`wholesaler`,`txt`) | input mode |
| `render_text` | TEXT NOT NULL | exact string sent to the model |
| `status` | enum(`pending`,`done`,`failed`) | |
| `model` | TEXT | e.g. `google/gemini-3.1-flash-image` |
| `cost_usd` | NUMERIC | from OpenRouter `usage.cost` |
| `sheet_path` | TEXT NULL | the 10-up sheet this plate came from |
| `plate_path` | TEXT NULL | the cropped single-name PNG |
| `created_at` | TIMESTAMPTZ default now() | |

Dedup: **by `student_id`** (grab-by-wholesaler). Re-run skips records already `status='done'` → progress = done/total. Two different students with the same name BOTH render (different IDs). Typed/txt jobs dedup by exact `render_text` within the job.

## 6. Inputs (3 modes)

1. **Type/paste** — textarea, one name per line.
2. **Grab by wholesaler** — pick a wholesaler → pull `students.full_name_third` for their students → list with done/pending status → "Generate remaining (N)".
3. **`.txt` upload** — one name per line, UTF-8.

**DEFAULT (confirm in review):** `render_text` = the name **exactly as given/stored, no auto-title.** (Matches the user's "the file contains the full text to render." For grab-by-wholesaler this renders `students.full_name_third` verbatim — no auto-prepended الأستاذ/الأستاذة.)

## 7. Generation

- Batch names into groups of **10** → one OpenRouter call per group.
- Call: `POST https://openrouter.ai/api/v1/images`, body `{ model, prompt, resolution:"2K", aspect_ratio:"9:16" }`, header `Authorization: Bearer <OPENROUTER_API_KEY>`.
- Prompt (tested, works): the "decorated vertical-list Thuluth" prompt — black ink, broad-nib contrast, one line per name, floated ornaments, no underlines/quotes/frames/numbering, "spell each name EXACTLY as written:" + the 10 names.
- Read `usage.cost` from the response → store per plate (cost/10).
- Save the returned sheet PNG → `/uploads/calligraphy/sheets/`.

## 8. Post-processing — crop sheet → individual plates

- `sheetCrop.js`: load sheet, compute per-row ink density (horizontal projection), find the blank gaps between the 10 lines, slice into 10 bands → one PNG per name → `/uploads/calligraphy/plates/`.
- Map each band to its `render_text` by order (top→bottom = input order). Store `plate_path`.
- **Deliverable DEFAULT (confirm in review):** both the **individual cropped plates** (one per sash, for the Fabric.js sash designer) **and** the full sheet.

## 9. Proof + re-roll

- Proof grid: each cropped plate shown next to its `render_text`. Admin (who knows the names) eyeballs.
- A wrong/ugly name → **re-roll just that one** as a single 1-name call (`resolution:"2K"`), swap the new plate into that record. (Never re-roll the whole 10-sheet.)
- Mark approved → status stays `done`.

## 10. Download

- ZIP of approved plates (named by `render_text` / student). Optionally include the sheets. Built server-side, streamed to the admin.

## 11. Error handling

- OpenRouter non-200 → mark group `failed`, surface Arabic error, allow retry (no double-charge: only persist `done` on success).
- Crop finds ≠ expected count of bands → flag the sheet for manual review rather than mis-slicing.
- Key missing/invalid → clear admin error; never expose the key client-side.

## 12. Acceptance tests

1. Type 23 names → 3 sheets (10/10/3) → 23 cropped plates, each matching its source line.
2. Grab wholesaler with 100 students, 40 already `done` → generates 60, progress shows 40→100.
3. Re-roll one plate → only that record's `plate_path` changes; cost increments by one 1-name call.
4. `usage.cost` persisted; admin sees total job cost.
5. Non-admin → 403 on every endpoint.
